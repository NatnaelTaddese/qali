# Qali for Mac

The native macOS app: an AppKit shell (window, menu bar, lifecycle) hosting
SwiftUI screens, drawn with Liquid Glass. It needs macOS 26.2 and Xcode 26 or
later.

## Run

```sh
brew install xcodegen   # once
scripts/run.sh
```

`project.yml` is the source of truth; `Qali.xcodeproj`, `Qali/Info.plist` and
`Qali/Qali.entitlements` are generated by `xcodegen generate` and gitignored.
Open the generated project in Xcode to work there instead.

Debug builds talk to the dev Convex deployment and Release builds to prod
(`Config/*.xcconfig`).

## Sharing a build

```sh
xcodebuild -project Qali.xcodeproj -scheme Qali -configuration Release \
  -derivedDataPath build-release -destination 'generic/platform=macOS' build
ditto -c -k --sequesterRsrc --keepParent \
  build-release/Build/Products/Release/Qali.app dist/Qali-<version>-arm64.zip
```

Release is arm64 only (ConvexMobile's prebuilt library has no x86_64 slice)
and needs macOS 26.2. With an Apple Development identity the app is signed
but not notarized, so on another Mac it opens only after Privacy & Security →
Open Anyway.

Debug is its own app, `com.myqali.macos.dev` shown as "Qali Dev", so it never
shares a sandbox container (settings, event cache) with Release. The Keychain
session and the cache files are also named for the deployment, so a dev
session is never sent to prod. Look a Debug build up by the `.dev` ID
(`defaults read com.myqali.macos.dev`, `~/Library/Containers/com.myqali.macos.dev`).
Its windows belong to "Qali Dev" in the window list; the process is still `Qali`.

## Signing

Builds are ad-hoc signed unless `Config/Local.xcconfig` names a team (copy
`Config/Local.xcconfig.example`). Use a real identity for day-to-day work: the
session lives in the Keychain, which is keyed to the code signature, so an
ad-hoc build is asked for access again after every rebuild.

`DEVELOPMENT_TEAM` is the certificate's organisational unit, not the ID in
brackets after your name:

```sh
security find-certificate -c "Apple Development" -p | openssl x509 -noout -subject
```

## Sign-in

Sign-in follows `@better-auth/expo`'s native flow (`Qali/Auth`): Google OAuth
runs in the default browser through `ASWebAuthenticationSession`, and the
session cookie comes back on a `qali://` callback. The backend has to trust
that origin, which is the `expo()` plugin and `nativeOrigins` in
`packages/backend/convex/auth.ts`.

## Looking at one screen

Debug builds take launch arguments that pin what the app shows, so a screen
can be checked without signing in again or clicking through:

| Argument | Effect |
| --- | --- |
| `-QaliScene launching\|signedOut\|signedIn` | Pin the top-level screen without touching the network |
| `-QaliView day\|week\|month` | Open the calendar on that view |
| `-QaliDate 2026-11-09` | Open the calendar on that day's page |
| `-QaliFixture events` | Swap the live events for a sample week with overlaps and all-day events |
| `-QaliCycle month,week,day` | Step through those views after launch, to watch the switch animations |
| `-QaliFling 2400` | Let the day strip go at that many points per second (negative scrolls back) 3 s after launch, to watch the horizontal glide without a trackpad |
| `-QaliStep 2` | Press Next that many times in quick succession 3 s after launch (negative presses Previous), to watch the arrows' glide |
| `-QaliToday YES` | Press Today 3 s after launch (pair with `-QaliDate` to start near or far from today) |
| `-QaliPillHover YES` | Show the Today/arrow toolbar pills as hovered, to capture their look without a pointer |
| `-QaliOverscroll 60` | Hold the hour grid that far down, as a pull past the top does, to see what an overscroll reveals |
| `-QaliSignOut YES` | Sign the restored session out at launch |
| `-QaliIsland account\|search\|event\|create` | Open that island panel a moment after launch (`create` lands on the next free half hour, as the + button does) |
| `-QaliSearch Lunch` | With `-QaliIsland search`, type that query and pick the first match (reveals and flashes it on the grid) |
| `-QaliGuestQuery an` | With `-QaliIsland create`, type that into the guest search to show its matches |
| `-QaliDraw 3,14,16` | Draw 14:00–16:00 on the page's fourth day and let go, as a drag down the grid does |
| `-QaliMove 2,1.5` | Pick up the page's first timed event 3 s after launch, hold it two days on and 1.5 hours later for 4 s, then drop it (with `-QaliFixture events` the drop is kept for 10 s and not saved) |
| `-QaliAllDay YES` | With `-QaliIsland create`, switch the new event to all day (its ghost moves to the all-day band) |
| `-QaliMonthPicker YES` | Open the toolbar month picker |
| `-QaliDescription demo` | With `-QaliIsland create`, open the description screen, write a formatted sample into it (logs the HTML under category `notes`) and return to the form two seconds later |
| `-QaliMeet YES` | With `-QaliIsland create`, switch the new event's Where row to Google Meet |
| `-QaliEventTitle Lunch` | With `-QaliIsland event`, open the first loaded event with that title instead of the first timed one |
| `-QaliDetail notes\|guests` | With `-QaliIsland event`, open the event's description screen or its guest list |
| `-QaliBandToggle YES` | Open the all-day band 3 s after launch and close it a second later |
| `-QaliPicker day\|time` | With `-QaliIsland create`, open the Starts row's day or time picker |
| `-QaliSwipe @-900,0;0,-600;f2400` | Play trackpad swipes (each `dx,dy` points, then momentum; `fN` lets the strip go at N pt/s) over the grid that's showing, 3 s after launch (`-QaliSwipeDelay 6` waits longer); delivered inside the app only |
| `-QaliFrameLog YES` | Print, every half second, how many display frames the main thread missed (pair with `-QaliSwipe` to measure scrolling) |

`scripts/shot.sh out.png` captures the window:

```sh
scripts/run.sh -QaliView week -QaliFixture events
```

## Layout

- `Qali/App`: the AppKit shell (window, menu bar, lifecycle) and app state.
- `Qali/Auth`: the Better Auth native flow and the Keychain cookie jar.
- `Qali/Data`: Convex subscriptions and the DTOs they decode.
- `Qali/Features`: the SwiftUI screens (sign-in, loader, calendar).
- `Packages/QaliDomain`: the calendar logic ported from `packages/domain`
  (paging, layout, zones, colours), with its tests.

## Design tokens and icon

Colours are generated from the web tokens, and the icon from the web icon's
recipe. Rerun these after either changes:

```sh
python3 scripts/gen-colors.py
swift scripts/gen-icon.swift
```
